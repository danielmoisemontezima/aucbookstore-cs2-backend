FUNCTIONAL REQUIREMENTS

These functional requirements define the specific features and operations that a system must perform to meet the needs of the institution's library and users. They describe what the system must do and how it interacts with users or other systems. We focus on the system's behavior and functionality. We represent the functionalities that can be directly observed and tested in the final product.
These functional requirements must answer the following questions:
What features should the system include? 
What specific cases or scenarios must the system handle?
The required functional specifications are:
A.manage User: users must be registered to have access
B.Catalogs and favorite: For users, view available products and add them to favorites if possible.
C.Add to carts: so that users can add the items they want to order, in order to keep track of their preferences
D.Search: To save more time, prioritize product searches.
E.Filter: to filter products, either by category or by price
F.Odders 
G.Paiement methods: to be able to choose your preferred payment method
H.Feedback: user reviews and feedback

NON FUNCTIONAL REQUIREMENTS
Non-functional requirements define how the system operates, prioritizing performance, reliability, and user experience over specific functionalities. They guarantee the system's efficiency, security, and maintainability over time, and define how the system should function (quality, performance, and constraints). These requirements will be invisible to users. 
These non-functional requirements must answer the following questions:
How quickly must the system respond to user actions?
What level of security must it achieve against unauthorized access?
